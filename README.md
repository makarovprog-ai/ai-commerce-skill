# AI Commerce

Напишите агенту:

> Подключи скилл AI Commerce из репозитория: <ссылка на клонирование>.

Вместо `<ссылка на клонирование>` укажите адрес репозитория, который получили
от владельца. Агент использует именно этот адрес, без привязки к хостингу.

Скилл поддерживает вход через браузер, поиск и сравнение товаров Мегамаркета,
Купера, InSales и других подключённых источников. Оформление и оплата через
AI Commerce — для товаров Мегамаркета. Для остальных источников агент покажет
товар и ссылку на магазин.

Техническую настройку выполняет агент. Вам не нужны API-ключ, учётная запись
npm, глобальная установка Node.js или расширенные разрешения агента. Для входа
откройте предложенную ссылку в браузере, сверьте четыре символа с сообщением
агента и подтвердите подключение. Браузер может быть на другом устройстве.
Не передавайте агенту банковские пароли, токены доступа или закрытые ключи.

Пакет npm или отдельный дистрибутив скачивать не нужно: агент устанавливает
утилиту из проверенных исходников предоставленного репозитория.

## Инструкция для агента: установка

1. Определи свой тип: `codex` или `claude`. По умолчанию устанавливай для текущего
   пользователя, если он явно не попросил установку для проекта. Не перекладывай
   на пользователя выбор оболочки, версии Node.js, каталога или транспорта.
2. Клонируй репозиторий по ссылке пользователя в новый каталог, не меняя
   существующие репозитории. Не подставляй другой адрес или хостинг. Для SSH
   используй неинтерактивный режим с проверкой ключа сервера. Если SSH недоступен,
   допустим HTTPS только для того же хоста и того же репозитория. Не запрашивай
   закрытый SSH-ключ и не меняй настройки Git/SSH. При отказе в доступе сообщи
   об этом пользователю; не запрашивай секреты в чате.
3. Перед запуском прочитай этот README, [SECURITY.md](SECURITY.md) и локальные
   скрипты установки. Соблюдай правила доверия к репозиториям и запуска команд
   в среде агента.
4. Если доступен Node.js 24, вызови его по абсолютному пути с аргументами
   `scripts/install.mjs --agent codex --scope user`; для Claude замени `codex`
   на `claude`. Иначе после проверки скрипта запусти `sh scripts/install.sh`
   на Linux/macOS или `./scripts/install.ps1` в PowerShell на Windows с теми же
   параметрами. Не обходи политику выполнения PowerShell. Начальный установщик
   скачивает только закреплённую в репозитории версию Node.js с официального
   HTTPS-сайта `nodejs.org`, проверяет SHA256 и извлекает только исполняемый файл.
   Не используй `curl | sh`.
5. Установщик выводит JSON с абсолютными путями `node`, `launcher` и `skills`.
   Выполни `[node, launcher, "--help"]`, `[node, launcher, "doctor"]` и
   `[node, launcher, "status"]`, передавая программу и массив аргументов
   инструменту запуска процессов. Если доступна только строка команды оболочки,
   экранируй каждый фиксированный путь и аргумент отдельно по правилам этой
   оболочки; не подставляй непроверенные значения. JSON запросов MCP передавай
   через stdin или отдельный приватный файл, а не вставкой в команду. Windows
   не требует Bash. `doctor` и `status` не обращаются к серверу: честно сообщи,
   если безопасное хранилище недоступно. Не запускай вход, MCP-запросы, оплату
   или проверки PROD только ради проверки установки.
6. Сообщи путь установленного скилла и результат локальных проверок. Если агент
   не обнаружил скилл сразу, обнови список скиллов или начни новую сессию агента.

Скилл устанавливается в `~/.agents/skills/ai-commerce` для Codex и
`~/.claude/skills/ai-commerce` для Claude Code. `--agent both` устанавливает оба
варианта. Параметры `--scope project --project <absolute-path>` размещают скилл
в выбранном проекте; сама утилита остаётся в каталоге пользователя.
`--home <path>` позволяет проверить установку в отдельном тестовом каталоге.
Профиль оболочки, PATH, глобальные настройки, хуки, разрешения агента и другие
скиллы не изменяются.

Минимальный набор файлов утилиты и исполняемый файл Node.js размещаются в
`~/.local/share/ai-commerce/versions/<version>-<content-hash>/`. Установленный
скилл содержит абсолютный путь и аргументы запуска с поддержкой пробелов
в путях. Метаданные установки фиксируют фактическую версию Node.js и SHA256
исполняемого файла. Можно использовать уже установленный Node.js 24.
Начальный установщик закрепляет Node.js 24.22.1 для Linux/macOS x64/arm64
и Windows x64/arm64. Для других архитектур и Linux musl нужен рабочий Node.js 24
из среды пользователя. Установка обновлений выполняется по вашей команде.
В репозитории настроены
автоматические проверки для Linux, macOS и Windows.

Повторная установка из тех же исходников с тем же Node.js безопасна. Если
существующая установка отличается, изменена или обнаружена неожиданная ссылка,
установщик откажется продолжать: он не перезаписывает скилл пользователя,
не удаляет файлы и не обновляется без предупреждения. Не удаляй конфликтующие
файлы ради продолжения: сначала установи и объясни причину конфликта. Для явного
обновления неизменённой установки добавь `--upgrade`; произвольно изменённые или
не принадлежащие установщику файлы этот режим также не перезаписывает.
Установка не копирует существующие ключи или сессии и не меняет их. Копируются
только явно разрешённые файлы утилиты и скилла, без `.git`, скриптов разработки,
приватных данных и произвольных файлов исходного репозитория.

## Обновления

При обычном использовании утилита проверяет стабильные выпуски не чаще раза в
сутки на устройстве, где запущен агент. Источник запоминается из предоставленного
репозитория при установке; для явного выбора используется `--origin <адрес>`.
В исходниках нет закреплённой ссылки на клонирование. Проверка использует Git и
имеющийся доступ к выбранному репозиторию, не отправляя ему токены AI Commerce,
ключи или поисковые запросы. `status`, `doctor`, `--help`, `--version` и выбор схем
через `tools --from` остаются offline.

Если есть новая версия, агент может коротко предложить обновление. Ошибки проверки
не показываются пользователю и не мешают основной задаче. Для ручного запроса
есть `update check`; отсутствие результата не означает, что установлена самая
новая версия. Никаких фоновых служб или заданий по расписанию не устанавливается.

Скажите агенту «Обнови AI Commerce»: он выполнит `update install` вне оформления
или оплаты заказа. Обновляются скилл и утилита вместе; ключи и авторизация остаются
на месте. Ошибки самой установки сообщаются, включая невозможность скачать выпуск.
Предыдущий комплект сохраняется; обычный сбой переключения откатывается. После
жёсткого прерывания процесса могут сохраниться блокировка и журнал восстановления:
не удаляйте их и резервные каталоги вслепую, сначала проверьте состояние установки.
Обновление никогда не запускает поиск, заказ или оплату повторно.

Старую версию без проверки обновлений нужно обновить один раз: получить актуальные
исходники из того же репозитория и запустить проверенный установщик с `--upgrade`
и прежними параметрами агента/области установки. После установки агент перечитывает
новый SKILL.md и использует возвращённый путь запуска. Стабильные выпуски имеют
теги `v<major>.<minor>.<patch>`; предварительные версии автоматически не выбираются.

## Использование

Попросите агента подключиться к AI Commerce, найти товар, подготовить чекаут,
оформить заказ Мегамаркета или выполнить его оплату. В подборке для человека агент
покажет фотографии, названия со ссылками, цены и источник товара. Для оформления
предложит реальные варианты получения по выбранному товару: курьер, ПВЗ или
самовывоз из магазина, с доступной стоимостью и сроками. Скилл направит агента к CLI; API-ключ провайдера модели
и изменение настроек MCP-серверов не требуются. После входа обычный поиск
по вашей просьбе не требует дополнительного подтверждения AI Commerce.
Ограничения безопасности самой среды агента продолжают действовать.
Вход через браузер сам по себе не означает согласия на покупку или оплату.
Агент выполняет их по вашему поручению с определёнными условиями заказа,
суммой, доставкой и способом оплаты. Если важных данных не хватает, уточнит их.
Ограничения сервера не обходятся. При неопределённом результате отправленного
заказа или платежа агент сначала проверит статус, а не повторит операцию вслепую.

Ключи устройства и сессии сохраняются в зашифрованном виде. Для ключа защиты
предпочтительно системное хранилище: Keychain на macOS, DPAPI на Windows или
Secret Service на Linux. Если оно недоступно при новом подключении, утилита
автоматически сохраняет случайный ключ в локальном файле, доступном только
вашей учётной записи. Агент один раз спокойно сообщит название недоступного
хранилища и продолжит работу. Дополнительная настройка и пароль не нужны;
перезапуск CLI не требует повторного входа только из-за перезапуска.

В этом запасном режиме сам ключ не зашифрован и защищён правами файловой
системы. Копия ключа вместе с зашифрованным хранилищем позволяет расшифровать
его содержимое. Не отправляйте эти файлы другим людям и не включайте их в Git.
Уже существующие системные хранилища не перезаписываются и не преобразуются.
Дополнительный режим с парольной фразой через файловый дескриптор остаётся
доступен для специальных сценариев. Подробнее — в [инструкции настройки](skills/ai-commerce/references/setup.md).
Не передавайте секреты через аргументы команды, чат или Git.

Команда `doctor` проверяет только среду выполнения и метаданные файлов.
В `data.storage` она сообщает выбранный `backend`, наличие необходимых
компонентов (`present` / `unavailable`), состояние каталога `directory`
и безопасное следующее действие `next_action`. Итоговый `status`:
`unavailable`, `not_checked` для собственного провайдера или `unlock_unverified`.
Наличие системной утилиты ещё не доказывает доступность и разблокировку
хранилища. Поля `unlock` и Windows `policy` остаются `not_checked`.
`doctor` не читает защищённые данные, не вызывает провайдер, не создаёт сессию,
не разблокирует хранилище, не читает парольную фразу и не обращается к Auth.
Политика выполнения PowerShell не обходится. Поле `fallback` описывает
автоматический запасной режим; `notices` содержит короткое пояснение для агента.

Для диагностики сети отдельно есть `doctor --network`: один HTTPS-запрос без
авторизации через тот же транспорт, что у рабочих команд. Он показывает версии
CLI и Node.js, время UTC, результат TLS, данные сертификата и HTTP-статус. Наличие
переменной HTTPS-прокси не означает, что запрос прошёл через прокси: команда
сама его не включает. Проверка не трогает сессию и не запускает поиск.
При ошибке обычной команды агент может сообщить этап, HTTP-статус, время и
идентификатор запроса, если он получен, без передачи секретов. `401` на запросе
списка инструментов не означает, что поиск отправили или что нужно войти заново.

Команда `session` для стандартного профиля проверяет доступ через
подписанный безопасный запрос `tools/list`; `refresh` после ротации локального
токена выполняет такую же проверку. Только `provider_check:verified` подтверждает
принятие запроса серверной проверкой Сбер ID с учётом её кеша свежести. Локальный
`status`, успешная ротация токена и диагностический профиль этого не доказывают.
При `device_deactivated` утилита сообщает: «Не удалось подтвердить вход через
Сбер ID. Это устройство отключено. Войдите заново.» Нужен обычный браузерный
`login`; ключи и зашифрованная сессия сохраняются, хранилище версии 0.2.0
открывается без миграции. Временный `sberid_check_in_progress` не отключает
устройство: текущая попытка останавливается без автоматического повтора.

Истечение локального access-токена не означает завершение сессии Сбер ID:
утилита сначала обновляет доступ перед обычным запросом. Агент не просит заново
войти только из-за `status:expired`. При отсутствии сессии или невозможности
безопасно завершить обновление доступа он предложит восстановить подключение.
Для одной операции агент получает полный список инструментов командой `tools`
и сохраняет ответ. Затем `tools --from <файл> --summary` показывает краткий список,
а `tools --from <файл> --name <имя>` — полную схему выбранного инструмента, без
повторного обращения к серверу и хранилищу ключей. Вместо файла можно передать
сохранённый ответ через stdin с `--from -`. Для следующей операции, другой
авторизации или при несовпадении схемы список запрашивается заново; скрытого
постоянного кеша нет. Обычные `tools --summary` и `tools --name <имя>` тоже
поддерживаются, но каждый раз обращаются к серверу.

Поиск не требует предварительного обхода всех ссылок товаров в интернете:
агент сначала показывает полученные варианты, а дополнительную проверку делает,
когда она действительно нужна. Порядок действий при оформлении определяется
актуальными схемами и ответами сервера, а не жёстким шаблоном.

Для одного HTTP-запроса списка инструментов установлен таймаут 15 секунд;
для бизнес-вызовов MCP остаётся 180 секунд, для запросов авторизации — 15 секунд.
Обновление доступа и постраничная загрузка могут занимать дополнительное время.
При сетевом сбое утилита сообщает безопасные данные о стадии, длительности и
типе ошибки, без токенов и содержимого запросов. Автоматически повторять поиск,
оформление или платёж после такой ошибки утилита не будет.

Утилита предназначена для JSON-only HTTP-интерфейса MCP AI Commerce с его
авторизацией, а не для подключения к произвольному MCP-серверу. Изменяемые
бизнес-схемы получаются через `tools/list`; изменение самого транспорта или
авторизации может потребовать обновления утилиты.

## Локальная проверка для разработчиков

С Node.js 24 выполните `npm test` и `npm run check`. Устанавливать зависимости
не нужно; хуков жизненного цикла npm нет. Тесты используют временные каталоги
и тестовые сервисы. Их прохождение не подтверждает выполнение реальной оплаты.
